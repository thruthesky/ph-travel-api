# 여행지 대장과 신규 후보 대조

`data.csv`는 실제 API에 수록된 한국어 여행지 한 곳당 한 행인 대장이다. 번역 8개를 8곳으로 세지 않는다. 후보·보류 항목은 `work/addition-candidates.csv`에서 관리하고 API 수록 수에 넣지 않는다.

## 갱신

```bash
node scripts/catalog.mjs
node scripts/candidates.mjs
node scripts/catalog.mjs --check
node scripts/candidates.mjs --check
```

대장은 한국어 JSON·다국어 이름·`sources/`·Git 기록에서 다시 만든다. 새 항목을 추가하거나 이름·사진·본문·출처를 고친 뒤 갱신한다. 콘텐츠 커밋 후 한 번 더 갱신하면 새 항목의 Git 최초 작성일·수정일도 채워진다. `--check`는 저장된 CSV와 현재 원본이 다르면 실패한다.

CSV는 Excel에서 한국어를 읽을 수 있는 UTF-8 BOM, CRLF, RFC 4180 인용 규칙을 사용한다. 필드 안 쉼표·큰따옴표·줄바꿈을 보존한다. 수식으로 해석될 수 있는 외부 문자열에는 작은따옴표를 붙인다. 전화번호의 `+` 등도 텍스트로 처리한다.

### 빈칸과 정확도

- 빈칸은 미확인이며 `없음`이나 `해당 없음`의 뜻이 아니다. 도시·섬·행사 전체에는 단일 주소나 연락처가 없을 수도 있다.
- 원본 위치에 `주`·`시` 접미사가 명시된 부분만 자동 분리하고 `원본 문장 분리·행정 관계 및 상세 주소 미검증`으로 표시한다. 주 이름이 없는 문자열을 지역 이름으로 추측하지 않는다.
- 바기오·세부시 등 확인한 독립 도시는 인접 주를 행정 소속 주로 자동 기입하지 않는다. 원본에 남은 지리적 표현은 `원본 위치 설명`에서 그대로 볼 수 있다.
- 상세 주소·연락처·별칭의 수동 보충은 `work/catalog-details.json`에 slug별로 둔다. `sources`·`checked_at`·필요한 `notes`를 함께 적는다. 대장 CSV를 직접 고치면 다음 갱신 때 사라진다.
- 지구와 바랑가이를 구분한다. 말라테·에르미타·산타크루스 같은 지구나 맥킨리 힐 같은 타운십을 바랑가이 칸에 임의로 넣지 않는다.
- 축제 전체의 주소·식별자를 주경기장의 주소·식별자로 바꾸지 않는다. 행사 좌표는 대표 지점이라는 한계를 메모한다.
- 최초 작성일과 수정일은 Git 기록상 파일 최초 추가와 최종 커밋 시각이다. 실제 집필일이 아니다. 미커밋 새 파일은 이 두 칸을 비운다. 파일시스템 수정일은 별도 열이며 체크아웃·복사에 따라 바뀔 수 있다.
- 본문 외부 링크와 근거 URL은 연락처 홈페이지와 다르다. 관광기사나 인용한 정부 페이지를 자동으로 해당 시설의 홈페이지로 쓰지 않는다.

## 추가 전 중복 확인

```bash
node scripts/duplicate.mjs --name 'Manila Zoo'
node scripts/duplicate.mjs --name '시눌록 축제' --latitude 10.3004 --longitude 123.8953
node scripts/duplicate.mjs --wikidata Q31479468
```

이름 정규화는 공백·문장부호와 라틴 문자 악센트를 정리한다. 한글·태국어·아랍어는 이름의 문자를 유지한다. 이름·별칭·확인한 외부 식별자 일치와 300m 이내 근접 항목을 보여 준다. **근접만으로 중복이라고 확정하거나 자동 삭제하지 않는다.** 성당과 광장, 도시와 축제, 동일 이름의 다른 해변은 별개일 수 있다.

이름 일치 없음도 신규 확정이 아니다. 기존 본문에서 해당 명소를 다루는지, 도시·지구 항목의 하위 명소인지, 오기·다른 표기가 있는지 조사한다. 실제 같은 곳이면 기존 항목을 보강하고, 별개로 방문 계획을 세울 수 있는 항목만 새로 추가한다.

`work/catalog-duplicates.md`는 기존 항목 간 동일 이름 키를 보고한다. 실제 별개인 동명 장소는 근거를 확인한 뒤 보충 정보의 `distinct_from`에 상대 slug를 적어 구분할 수 있다.

## 필고 후보 CSV

`scripts/candidates.mjs`는 앞선 팀의 2025-08-10 이후 TSV와 이전 글 후보 CSV를 읽고 **현재 `data.csv`**에 대조한다. 한국어 JSON SHA256 또는 수록 수가 대장과 다르면 먼저 대장을 갱신하도록 실패한다.

- 같은 이름과 확인한 축제 표기 차이만 보수적으로 묶는다. 묶은 후보에도 다른 이름의 중복·주제 글·업소가 남아 있을 수 있다.
- `기존 독립 항목·추가 제외`: 이름·별칭이 대장과 일치한다.
- `기존 지구 항목에 수록·분리 여부 검토`: 이전 팀이 지구·복합시설에 포함한 결과를 유지한다. 하위 시설 이름을 지구의 동의어로 바꾸지 않는다.
- `본문 언급·독립 항목 여부 검토`: 기존 본문에서 이름을 찾았으므로 별도 항목 필요성을 판단한다. 단순 문자열 검색 결과라 문맥 검토가 필요하다.
- `이전 검토 보류·재확인 필요`: 사진 부족·폐쇄 등 이전 팀의 사유를 유지한다.
- 나머지는 여행지 적합성·최신 출처·사진부터 확인한다. 본문이 긴 글을 먼저 보도록 최장 글자 수 내림차순으로 정렬한다.

후보 수를 API 항목 수로 세거나, 후보에 8개 언어 파일을 복제해 수록 수를 늘리지 않는다. 신규 항목도 기존 규격인 한국어 본문·검증 사진 10장·출처·7개 번역·빌드 검사를 모두 거친다.

## 1,000번 이후 파일

`001-…json`처럼 최소 3자리로 쓰되, `1000-…json`부터는 자릿수를 늘린다. 빌드·번역 파일 탐색과 번호·slug 조회는 4자리 이상을 인식하고 ID 숫자순으로 정렬한다. 임시 데이터 폴더의 실제 999/1000번 빌드와 번역 내보내기로 검증한다.

```bash
node --test scripts/catalog.test.mjs scripts/place-files.test.mjs scripts/large-id.test.mjs
```

## 두 전체 게시글 목록을 대조할 때

`node scripts/audit-post-registration.mjs`는 이전388글 CSV와 이후1,153글 TSV 전체를 현재 JSON·별칭·본문 및 공개판 스냅샷과 대조한다. 결과와 한계는 [전체 수록 대조 보고서](philgo-registration-audit.md)에 있다. 기존 `candidates.mjs`의 필터된 후보 목록과는 범위가 다르며, 이름 미검출을 확정된 신규 여행지로 해석하지 않는다. 원본 파일의 내용과 공개판 스냅샷 시각도 확인한다.
